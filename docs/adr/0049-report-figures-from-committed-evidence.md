# ADR-0049: Report figures are rendered from committed evidence, never from a model

- **Status:** accepted
- **Date:** 2026-09-03 (UTC)

## Context

The brief asks `reports/CHALLENGER_EVALUATION.md` to carry the pseudo-prospective comparison **with
plots**. It had none: three models, two regions, 55 windows each, and every claim in the document
was a pooled number in a table. The arguments that matter most in it — "a positive mean information
gain carried by one window in ten is not a win, it is a heavy tail", and "on Nepal the leak flips
the sign" — are arguments about *shape*, and a table is the wrong instrument for shape.

The obvious way to add plots is to make the scoring run draw them. That is how the pycsep bundles
under `reports/protocol/*/eval/` were produced, and it is fine for per-forecast diagnostics. It is
the wrong choice for the figures in an evaluation document, for two reasons.

First, a figure produced inside a scoring run can only be regenerated by repeating that run. The
gridded and ensemble *fits* are not retained (`RELEASE_STATUS.md`); the NTPP schedule took hours.
A reader who wants to check a figure would have to refit.

Second, and worse, a figure drawn from live model state can silently disagree with the numbers in
the document beside it. The two would then have different provenance, and the reader has no way to
tell which is stale.

## Decision

Figures in `reports/*.md` are rendered by a separate package, `src/rupture/reporting/`, whose only
inputs are files already committed to the repository.

`rupture.reporting.challenger_plots` reads exactly four kinds of file —
`reports/challenger/<region>/schedule-<region>-challengers.json`,
`reports/protocol/<region>/eval/schedule-<region>-ntpp.json`,
`reports/protocol/<region>/eval/ablations-<region>-ntpp.json` — and writes PNGs next to them. It
imports no model, loads no weights, issues no forecast and refits nothing. Run it with

```
uv run python -m rupture.reporting.challenger_plots
```

Three rules make it trustworthy rather than merely convenient.

1. **A missing input is an error, not an empty panel.** `MissingEvidenceError` names the file. A
   plot of nothing is a plot of something that did not run, and it would read as a result.
2. **Undecidable is not zero, and undecidable is not failure.** A window with no target event has
   `passed: null` on its consistency tests and a meaningless `0.0` T-statistic; those windows are
   dropped from the denominator and not drawn, exactly as the schedules' own pass rates do.
   Reading `passed: null` as `False` would have invented 33 Nepal failures nobody measured — the
   first draft of this module did precisely that, which is why the rule is written down.
3. **Series that were not scored on the same issue times are never drawn on one axis.** The loader
   compares issue times across all four schedules and raises if they differ.

The ETAS line in these figures is the **matched re-run** carried inside the NTPP schedule (no
refits, 100 continuations), which is what the challengers were actually compared against — not the
published baseline of record in `docs/BASELINE_RESULTS.md`, which uses yearly refits and 1000
continuations. Mixing the two would flatter or damage a challenger by accident. Both are stated
wherever either appears.

The rendered PNGs are committed under `reports/challenger/<region>/`, beside the JSON they were
drawn from.

## Consequences

- Any reader can regenerate every figure in the challenger evaluation from a fresh clone, offline,
  in about two seconds, with no fit and no network.
- A figure cannot drift from the document's tables, because both quote the same committed JSON.
- `src/rupture/reporting/` is a new top-level package that the import-linter contracts do not
  mention. Nothing imports it and it imports only `matplotlib` and the standard library, so the
  exposure is small — but it is recorded in `RELEASE_STATUS.md` § Known gaps rather than left for
  someone to notice.
- `reports/` is ignored by `.gitignore` apart from explicit negations, so the PNGs are force-added.
  They are tracked, so `make clean` (`git clean -fdX reports`, which removes only *untracked*
  ignored files) leaves them alone. The negation should be added so the state is declared rather
  than inherited from a force-add.
- The module has no unit test. It is exercised by being run, and its output is committed and
  reviewable; a test asserting the undecidable-window rule against a small fixture would be worth
  having and does not exist.

## Alternatives considered

- **Draw the figures inside `protocol_runner.py` / the challenger schedule command.** Rejected for
  the two reasons in Context: irreproducible without a refit, and able to disagree with the
  document.
- **Commit figures produced by an ad-hoc script that is not in the repository.** Rejected outright.
  A figure whose generator is not committed is a figure nobody can check, which is the same failure
  mode as a number without provenance.
- **Use the pycsep plotting helpers.** They draw per-forecast consistency-test distributions, one
  window at a time; the question here is about 55 windows at once.
